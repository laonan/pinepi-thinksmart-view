# PinePi Home

[English](README.md) | **中文版**

面向 Lenovo ThinkSmart View 的自定义 Android Home Launcher APK。运行与验收基线为 **Android 8.1.0 / API 27**，保留现有 ROM、蓝牙音频能力和原桌面。项目背景见 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.zh-CN.md)。

## 当前阶段：Material 3 主 UI、消息协议 v2 与百度 TTS（0.8.2）

消息发送、完整 JSON 字段、五种示例、ACK、媒体限制和本地提示音生成步骤见 **[消息协议与使用说明](docs/MESSAGE_PROTOCOL.zh-CN.md)**。v2 支持普通文本朗读、隐私文本本地提示，以及图片/音频/视频 URL；旧 v1 文本保持静默兼容。0.8.1 已接通百度短文本 TTS，四段固定提示音已内置；HTTP 发布 TEXT/TTS 时省略 speech 可由 Hub 合成。用户确认四段提示音和正文朗读均完整听到。隐私正文不进入该供应商路径；新闻采集、定时播报、长文本分段及音频/视频主体播放仍单独实施或验收。

- Kotlin + Material 3 Compose 主 UI，单个 `app` 模块；原生 View 保留在隐藏调试页。无 WebView；接近唤醒与 Hub 继续使用独立前台服务。
- 声明 `MAIN + HOME + DEFAULT`，可通过系统选择为默认桌面；同时保留应用列表启动入口。
- 消息主页、对话页与设置页；原全屏测试页完整保留为隐藏二级调试页。消息独占内容区，左右滑动，底部显示当前位置与总数；最新 10 条保存在应用私有目录。
- 公共 Settings Intent 打开 Wi-Fi、蓝牙、系统和默认桌面设置；具体页面不可用时回退系统设置。
- 枚举其他 Home 应用，通过用户选择显式打开，作为原桌面维护入口。
- 设置页版本号连续点击 7 次（相邻点击间隔不超过 3 秒）进入调试页，保留设备信息、录音/回放、蓝牙、接近及 Hub 诊断；返回键回到设置。

0.2.0 使用 AudioRecord 采集 16kHz、单声道 PCM16 并封装 WAV，MediaPlayer 本地回放。麦克风只在用户点击开始且授权后使用；授权成功需再次点击。结束后释放麦克风，取消、退到后台或旋转重建页面时停止并清除本轮录音。测试上限 30 秒是本地验证参数，不是冻结的 V1 会话规则。录音只保存在应用私有缓存，进程重启时清理遗留测试文件；不上传、不记录音频正文。

0.2.1 针对实测录音偏弱加入两种公开输入来源对照：`VOICE_RECOGNITION` 和 `MIC`。切换输入会清除上一轮录音，不代表已确认某种输入适用于当前 ROM。界面显示精确峰值百分比、略过起始 0.2 秒的录音平均 dBFS、媒体音量和系统麦克风静音状态。低于 -45 dBFS 仅给出“偏弱”提示，不识别人声或修改音频。扬声器测试通过同一 MediaPlayer 路径播放本机生成的三声 660Hz 短音，不使用麦克风、不覆盖现有录音。音量键控制媒体流，应用不自动提高系统音量。

0.2.2 修正播放被蓝牙检查拦截时的反馈：蓝牙状态在音频卡片内直接显示，点击被拦截的测试音/回放会明确提示“尚未开始播放”。冷启动状态待确认时需保持主页前台，用手机连接再断开一次；断开后重新点击播放。播放不会排队自动开始，只有录音入口的等待支持检测断开后继续。

0.2.3 根据实测普通 `MIC` -48.6 dBFS、语音识别输入 -53.9 dBFS，暂将默认输入改为普通 `MIC`。加入默认关闭的“增强回放”复选框，通过系统 `LoudnessEnhancer` 为本次录音播放提供最高 +24 dB 增益；仅绑定本应用 MediaPlayer 的正数会话 ID，不绑定全局会话，不作用于测试音或蓝牙音乐，不改原始 WAV、系统音量或麦克风配置。停止、取消和离开页面会释放效果；无法启用时明确提示并按原音播放。它是试听对照手段，不代表已经解决原始采集偏弱或提高了信噪比。接口依据：[Android LoudnessEnhancer](https://developer.android.com/reference/android/media/audiofx/LoudnessEnhancer)。

0.2.4 针对实测约 35ms 处的近满幅麦克风启动脉冲，先进行 200ms 预热并丢弃该段 PCM；页面由“准备麦克风”切换到“正在录音”后再开始说话。有效 PCM 起始 20ms 淡入，结束时最后 20ms 淡出，避免波形边界突变。平均电平按有效捕获帧计算，不含预热段；试听增强仍不改保存的 WAV。测试总上限包含预热时间，有效录音会略短。用户已确认新录音的起始爆破声消失，增强试听音量可接受，但声音有些浑浊。当前参数作为本地验证基线保留，清晰度仍待优化；不能据此认定原始采集偏弱已解决或语音识别质量已通过。

蓝牙检测使用 API 27 的公共适配器连接广播，覆盖所有 profile 的连接变化，不能将它当作精确的 A2DP 接收端连接/播放查询。进程刚启动且蓝牙开启时显示“待确认”，不会把缺失状态当作断开；保持主页前台，在手机端连接再断开一次以建立观测。等待期间可取消，检测到全部断开后继续本地录音流程；若录音/回放中出现连接或未知状态，则取消。系统缺少广播或无法确认断开时保持阻止，不自动关闭蓝牙、不扫描、不强制断开、不调用隐藏 profile API。

0.2.4 已通过用户操作与 ADB 状态核验：录音中取消、录音中进入设置、录音中手机蓝牙重连，均停止采集并清空缓存；取消蓝牙等待后再断开手机，没有自动录音。增强回放中取消可立即停声，并释放音频焦点、效果链及录音文件。回放中进入设置/蓝牙重连、准备阶段取消、旋转与熄屏等组合尚未全部实测，详见验证记录。

传感器诊断显示接近传感器名称、系统 wake-up 标记和前台实时读数。0.2.4 已实测 `VCNL4200 PRX`：手靠近为 0.0、移开为 5.0，用户反馈与 ADB 新事件一致且可重复。

### 语音播放音量（0.8.2）

设置 → **语音播放音量** 保存消息播放的媒体音量下限，直接使用设备档位 **1/15 … 15/15**，默认 **14/15**。本地到达提示音、正文朗读、手动播放音频消息，在准备完成且即将播放时，如果当前媒体音量低于下限才临时提高；已有更高音量不降低。下载期间、蓝牙保护阻止播放时、调试录音/试听均不提音量；视频播放器主体仍使用普通媒体音量。

播放结束、取消、报错、被中断或离开主页时，先恢复原音量，再释放音频焦点。播放期间按音量键或观测到外部音量变化，则保留用户调整。恢复覆盖正常播放与生命周期清理，不包含进程被强杀或突然断电。使用设备实际媒体音量档位，不做百分比转换。蓝牙音乐仍受原有“确认断开后才播放消息”规则保护，不自动断开，也不排队补播。

## 开发注意事项

### USB 数据线与上电顺序

本设备开发调试使用已验证的 **A → C 数据线连接路径**：USB-C 端接 ThinkSmart，Mac 端按已验证的 USB-A/转接头路径连接。此前 C → C 路径未能识别本设备，尽管同一线能正常连接三星手机；具体兼容原因尚未确定。

冷启动或断电后按以下顺序连接（2026-10-30 实测恢复成功）：

1. ThinkSmart 的 USB 数据线先保持断开。
2. 只连接设备电源，等待完全进入 PinePi 桌面。
3. 再接 A → C 数据线，保持“USB 调试”开启；Mac 若询问是否允许配件连接，选择允许。
4. 执行 `adb devices -l`，确认序列号 `HUA0BQMQ` 的状态为 `device`，再运行安装/调试命令。

若设备未被识别，恢复流程是：拔下 ThinkSmart 的 USB 和电源，等待约 10 秒，再按上述“只接电源 → 进入桌面 → 接 USB”顺序操作。不要在安装、更新或正在写入重要数据时断电。这是本机已成功的操作经验，尚不能断定为某种控制器或 USB 角色协商问题。

已授权过的 Mac 再次连接时可能不再弹 RSA 指纹框；不要把“没弹框”当作未连接或未授权的唯一依据。若 `adb devices` 完全没有设备，应先检查 Mac 是否识别到 USB；`unauthorized` 才转向授权检查。通常不必重新设置开发者模式或反复撤销授权。

必要时在 ThinkSmart 的 Termux 分别读取 `getprop sys.usb.state` 与 `getprop init.svc.adbd`，本机成功时为 `diag,adb` 和 `running`。这两个值正确仍不能证明 USB 已成功枚举；2026-10-30 就出现过值正确但 Mac 无设备、按上电顺序恢复后才连通的情况。详细证据见 [冷启动后 USB 连接恢复](docs/DEVICE_VALIDATION.zh-CN.md#冷启动后-usb-连接恢复2026-10-30)。

### 网络 ADB 与多设备选择

本机 USB 序列号为 `HUA0BQMQ`。无线 ADB 需要先通过已授权 USB 开启，断电/重启后可能需要重新开启。IP 会变化：2026-10-29 为 `192.168.2.101`，2026-10-30 用户提供 `192.168.2.108`。以下使用后一个地址，实际操作先核对设备 Wi-Fi 详情：

```sh
adb -s HUA0BQMQ tcpip 5555
adb connect 192.168.2.108:5555
adb -s 192.168.2.108:5555 shell getprop ro.build.display.id
```

上述方法此前已实测成功，当前新地址尚未重新启用无线 ADB；5555 端口拒绝连接时先恢复 USB，再执行 `tcpip 5555`。Android Studio 可选择已连接的 `<当前IP>:5555` 为运行目标。USB 与无线同时在线或连接了其他手机时，每条命令显式使用 `-s` 选择目标；USB 可以一直保留，无需为了无线调试拔掉。此配置只用于可信开发局域网，调试结束可通过 `adb -s HUA0BQMQ usb` 切回 USB 模式。

### 已知问题与维护边界

- 唤醒时导航栏短暂闪现：用户确认不影响使用，作为低优先级已知问题保留关注，不阻塞 Hub 开发。继续保留系统设置、其他 Launcher 的导航能力，不为消除闪现禁用 SystemUI 或系统导航。
